Learning curve — holdout accuracy, memory on vs. off

Reads ledger/learning_curves/{domain}_memory_on.jsonl and ..._memory_off.jsonl (written by evals/learning_curve.py, TASK 13). Each line is one train-then-holdout pass; the y-axis is that pass's holdout accuracy. If the "on" line rises while "off" stays flat, memory made the same unmodified agent code measurably better. Domains are hardcoded below (LEARNING_CURVE_DOMAINS) because a static page can't list a directory over file://.

Memory growth

Reads memory/{domain}/entries.jsonl directly — the same append-only, one-record-per-write log core/memory.py writes and folds. There is no separate timestamp field on a MemoryEntry, so "over time" here means chronological write order in that file (the x-axis is the Nth write to the ledger, not a wall-clock date). At each write, the chart replays every record up to that point and counts current entries by scope (stacked) plus retired and merged entries (also stacked, never dropped from the log per that module's append-only design) so compaction and retirement stay visible rather than looking like entries vanished.

Memory inspector

Every memory entry ever written for a domain, folded to its current state (latest record per id, exactly like core/memory.py's own read path). Search matches content, trigger, id, source run, or evidence task ids. Every row carries its source_run_id, evidence_task_ids, and created_gen (the pass it first appeared in) — that's the full trace back to the run/task that produced it, per AGENTS.md's traceability requirement.

Cost & latency vs. accuracy, across passes

Same per-pass records as the learning curve view, re-plotted against cost_per_task and p50_latency_ms (both already recorded per pass by evals/learning_curve.py). Points are connected in pass order so you can see whether accuracy improved without cost/latency creeping up. There is no routing/no-routing comparison here — step-level model routing (TASK 15) was skipped for budget reasons, so this is the existing routing-less cost data only.
