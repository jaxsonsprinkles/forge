Forge Dashboard

Reads ledger/generations.jsonl, one JSON record per completed generation (written by core/loop.py via core/ledger.py). Static HTML/CSS/JS only — no build step, no framework.

Improvement curves

Accuracy of the agent lineage's baseline (scores_before) at each generation, per domain. Train and holdout are plotted as separate series where both are present in the ledger.

Cost vs. accuracy, every evaluated variant

Simplification: a static page can't list the contents of agents/archive/ (no directory index over a plain file server), so this plots every candidate ScoreCard actually recorded in the ledger's results field for each generation — i.e. every mutation that produced a scoreable candidate, not only the ones gate.py archived as non-dominated. Each point averages a candidate's per-domain ScoreCards. Filled points are that generation's winner; hollow points were not selected; the baseline going into each generation is shown as a square.

Generations

"Accepted" marks the mutation matching that generation's winner_id; everything else is "rejected". gate.py's exact rejection reason (watchlist failure / accuracy floor / no meaningful improvement) is only logged at runtime, not persisted onto the Generation record, so it isn't reproduced verbatim here — compare a candidate's own scores against the baseline column to see why it likely lost.
